## 真实公共行情

实际运行本地服务，两个 BTCUSDT 客户端加一个 ETHBTC 客户端，每组收集 120 个有效帧：

| 市场 | 实测推送频率 | 计算及帧组装 p95 | 平均 JSON 帧大小 | 1/5bp 覆盖 | 观察到的成交缺口 |
|---|---:|---:|---:|---|---:|
| BTCUSDT | 10.06 Hz | 2.276 ms | 25,271 bytes | 完整 | 0 |
| ETHBTC | 10.00 Hz | 1.156 ms | 18,974 bytes | 完整 | 0 |

两个 BTCUSDT 客户端实际收到相同时间、序号及 mid 的共享快照；测试期间活动市场数为 2。ETHBTC 的报价单位确认为 BTC，未误用 USDT。

这是当时行情下的短时观测，不能推断所有市场时段的最大吞吐量。计算耗时不含 JSON 文本序列化、网络传输和浏览器绘制。

## 浏览器交互

- 输入 `ETH/BTC`，正确订阅 ETHBTC，价格精度及基础币／报价币同步更新。
- 输入不存在的 Symbol，原有订阅保持，输入框提供原生校验反馈及提示。

- 桌面 1440×1100 和手机 390×844（DPR 2）检查布局，无页面横向溢出；表格在自身容器内滚动。
- 已在正常页面看到真实吸收／补量事件，不靠演示数据填充空态。

## JavaScript 绘制测量

最终实现使用数字／时间格式器缓存、固定盘口 DOM 节点、Canvas、按横向像素保留极值的绘图采样。指标计算和导出继续使用原始采样点。

使用 `await microScope.benchmark(180)`，将已经观察到的真实样本重复至 9,000 点，用于覆盖 15 分钟缓存容量；按 `requestAnimationFrame` 连续提交 180 帧。测试环境为现有 Chrome 会话，1440×1100、DPR 1，其他浏览器标签页仍存在。

| 测量 | 最终一次记录 |
|---|---:|
| JS 更新 + Canvas 提交中位数 | 10.4 ms |
| JS 更新 + Canvas 提交 p95 | 17.1 ms |
| 单独 DOM 更新 p95 | 2.7 ms |
| 单独 Canvas 提交 p95 | 15.5 ms |
| 最大单帧 | 45.5 ms |
| 小于 16.7ms 的帧比例 | 93.9% |
| 随后正常 10Hz 行情的绘制 p95 | 11.2 ms |

DOM 和 Canvas 的 p95 分别统计，不能直接相加。以上是 JavaScript 执行及绘制命令提交的耗时，不包含 GPU 合成或完整端到端延迟。绘图会受到硬件、DPR、扩展及其他页面负载影响，不能保证所有设备稳定 60fps。

当前实际推送周期为 100ms，以上测量支持使用 JavaScript + Canvas 完成这一刷新率。暂不引入 WebAssembly；如果未来要在浏览器计算跨市场特征、增加大量同时显示的热图，需在目标设备重新测量计算与绘图瓶颈，再决定 Worker、OffscreenCanvas 或 WASM。
